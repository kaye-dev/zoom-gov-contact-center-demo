# Zoom公式情報の参照規約

Zoomの機能、制限、提供条件、API、SDK、Webhookについて判断する調査、設計、実装、レビューに適用する。Zoom仕様に関係しない変更には、この規約による追加調査を要求しない。

## 情報源の選択

Zoom公式の一次情報を最優先する。次の分類を検索の優先先とし、ドメインだけでなく文書の用途と対象への適合性で根拠を選ぶ。

| 分類 | 対象 | 用途・制約 |
|---|---|---|
| Tier 1（正式仕様の根拠） | `support.zoom.com`、`developers.zoom.us`、`library.zoom.com`、`www.zoom.com` | 正式仕様の根拠を優先して探す。APIは該当リファレンス、設定・要件はSupport、構成設計はTechnical Libraryを優先する。製品紹介から詳細仕様を推測しない |
| Tier 2（用途限定の公式情報） | `marketplace.zoom.us`、`zoom.us`、`www.zoom.us`、`status.zoom.us`、`zoomstatus.com` | 掲載アプリ、認証・サービス案内、稼働状況など、そのページが直接扱う用途に限定して一次情報として扱う。掲載アプリの情報をZoom製品全体の仕様へ一般化しない |
| Tier 3（参考情報） | `community.zoom.com` | 調査の手掛かりとして扱う。公式文書で裏付けられない投稿を正式仕様の根拠にせず、参考情報・未確認と明示する |

- 公式文書からリンクされた別ホストの資料は、発行元と用途を確認して扱う。
- Zoomのドメイン配下という理由だけで、投稿内容を正式仕様と判定しない。

## 根拠の確認と不確実性

- 検索結果の要約だけで判断せず、根拠ページの本文を確認する。
- 対象製品、バージョン、商用版・Governmentなどの提供環境、ライセンス、地域、GA・Beta・提供予定の適合性を先に確認する。将来のリリース予定を現在利用可能な仕様として扱わない。
- 同じ適用条件の資料では、更新日と仕様の適用日を比較して新しい情報を優先する。更新日不明は不明とし、検索エンジンのクロール日を更新日として扱わない。
- APIの実装判断では、該当エンドポイント・イベントの認証、必要scope、入出力、制限と関連する変更履歴を確認する。
- 公式文書間の矛盾は、両方のURLと相違点を示す。解消できない場合は断定せず、影響する実装判断を未確定として残す。
- 根拠が見つからないことを「非対応」の証明にしない。閲覧できない資料も確認済みと扱わず、未確認事項とその理由を示す。
- 公式仕様、実環境での観測、推論を区別する。実機結果を製品全体の保証へ一般化しない。

## 回答と設計判断への記録

- Zoom仕様に関する主張・実装判断の近くに、根拠となる公式ページのURLを必ず添える。該当する記述へ結び付け、トップページだけを出典にしない。公式の根拠を確認できない場合は、その旨を明示し、URLや裏付けを推測で補わない。
- 継続利用する設計判断は、既存の設計・機能ドキュメントやgoalの関連箇所に「採用する仕様／公式URL／確認日／適用条件／未確認事項」を記録する。
- 新しい証跡台帳や必須テンプレートは追加しない。過去の文書を一括で書き換えず、今後扱う判断から適用する。
- 本規約を正本とし、各スキルへ本文を重複転記しない。
