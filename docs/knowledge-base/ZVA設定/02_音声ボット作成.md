# 音声ボット作成

## 予約対応を音声Agentへ追加する

予約APIを使用する場合は、先に[予約APIツールテンプレート作成](./04_予約APIツールテンプレート作成.md)の8件を作成、確認します。部分更新以外の7件をDebugし、部分更新は同手順の安全分岐を反映して保存後に読み戻した場合だけDebugします。その後、Skill Libraryの`未来市の予約案内・予約管理`を保存後に監査します。実際の読み上げ方と合格条件は[予約デモのトーク例](./05_予約デモトーク例.md)を使用します。

予約操作を含む構成は、利用者認証と予約所有者検証をAPI側で保証するまで、管理者が制御するドラフトAgentの`テストを開始`による非公開テストだけに限定します。Agentへチャネルを追加せず、API側の検証と対象チャネルの公開判断が完了するまでPublishしません。

### スキルを設定する

1. 対象の音声Agentを開き、`ドラフト`でチャネルが未接続であることを確認します。
2. `スキル`で`問い合わせ確認中の先行応答`が存在し、`Active`であることを確認します。存在しない場合は追加を推測せず、この手順を停止してSkill Library版と対象Agentの互換性を確認します。
3. 2026年9月1日に確認した対象音声Agentでは、Generalスキル`未来市の予約案内・予約管理`の`ライブラリから追加` → `Use`が`skill.channel=3 incompatible with agent.channel=2`で失敗します。同じ失敗操作を繰り返さず、スキル一覧の`スキルを作成`を開きます。別のAgentで追加を試す場合も、同じエラーが表示されたら停止します。
4. Skill Library版と同じ名前、トリガー、指示を設定し、`スキルライブラリに追加`はオフにします。
5. `挿入` → `ツール`から次の7件を各1件追加します。各ツールの`ツールの確認と追加`では、保存済みの静的Authorizationを外部へ表示、コピー、変更せず、同一アカウントの承認済み設定であることを確認して`保存して追加`を実行します。

   - `mirai_reservation_list_services`
   - `mirai_reservation_get_availability`
   - `mirai_reservation_create`
   - `mirai_reservation_get`
   - `mirai_reservation_replace`
   - `mirai_reservation_delete`
   - `mirai_reservation_update_partial`

   `mirai_reservation_list`は追加しません。予約一覧はAPIキー単位であり、会話中の利用者単位に分離されていないためです。

6. スキルを保存し、一覧で`未来市の予約案内・予約管理`が`Active`であることを確認します。

Zoom公式手順はスキルのモダリティとしてGeneral、Voice、Chatを案内していますが、実測エラーに含まれる内部チャネル番号の対応関係は公開していません。そのため、エラー文字列をモダリティ番号の仕様として一般化せず、対象Agentごとに追加結果を確認します。

Agent内で作成したスキルはSkill Library版とは別管理です。ツールテンプレートまたはSkill Library版を変更しても自動同期されたと扱わず、Agentローカル版の指示と7件のツール参照を開き直して手動で照合します。

Agent guidanceの禁止事項は権限制御ではありません。7件のツールを持つ予約スキルを`Active`にしたまま公開せず、公開前にはAPI側の利用者認証と予約所有者検証を実装して検証するか、予約スキルを無効化して`mirai_reservation_list_services`と`mirai_reservation_get_availability`だけを参照するread-onlyスキルへ置き換えます。

`mirai_reservation_update_partial`は、GET非200の安全分岐をZoom側テンプレートへ反映し、正常系200と制御された404を再Debugするまで完了扱いにしません。この既知未確認が残る間は、`テストを開始`で実会話を行う前にAgentローカルスキルから同ツールを外し、残り6件だけを参照させます。再Debugと保存後の読み戻しが完了した場合だけ同ツールを再追加します。Agentは引き続きドラフトかつチャネル未接続に保ちます。

### Agent guidanceを設定する

`エージェントのガイダンス`の末尾へ次を追加します。

```text
【予約対応】

- 予約可能なサービス、空き枠、予約IDによる内容確認、予約の作成、変更、取消には「未来市の予約案内・予約管理」を使用してください。
- 予約に関するナレッジ確認またはツール実行が必要な場合は、本回答の前に「問い合わせ確認中の先行応答」を一度だけ使用し、その発話を完了してから予約スキルを使用してください。挨拶、すぐ回答できる確認質問、同じ処理の継続中には繰り返さないでください。
- 予約操作を許可するのは管理者による制御された非公開デモとPreviewだけです。API側で利用者認証と予約所有者検証が保証されていない公開チャネルでは、サービス一覧と空き枠の案内だけを行い、予約詳細の取得、作成、変更、取消を実行しないでください。
- 予約一覧は使用しないでください。既存予約は利用者が提示した予約IDだけで取得し、他の予約を検索、列挙、推測しないでください。
- serviceKeyがbulky-wasteの場合はサービスと空き枠の案内だけを行い、予約作成、変更、取消、料金算定、受付番号発行、予約確定を行わず、正式な受付方法を案内してください。
- 予約作成前にサービス、日付、時刻を提示し、利用者の明示的な確定意思を得てください。同じ予約意図には同じIdempotency-KeyとexternalReferenceIdを使用し、新しい識別子で重複作成しないでください。
- 変更または取消の前に予約IDで最新内容とversionを取得し、変更前後または取消対象を提示して明示的な同意を得てください。同意対象のversionからstrong If-Matchを作成してください。
- 412、非2xx、応答不明など変更結果が曖昧な場合は自動再実行しないでください。最初に予約を再取得し、現在内容とversionから適用済みかを確認して説明してください。追加操作が必要なら再度明示的な同意を得てください。エラー時は成功と案内しないでください。
```

文面を貼り付けた後、`挿入` → `スキル`から`未来市の予約案内・予約管理`と`問い合わせ確認中の先行応答`を各1件追加し、構造化されたスキル参照として保存します。文面中のスキル名だけを参照設定済みの証拠にしません。

保存後に画面を再読み込みし、予約スキルと先行応答スキルがどちらも`Active`、`mirai_reservation_list`が0件、Agent guidanceの予約対応節と2件のスキル参照が保持されていることを確認します。部分更新の既知未確認が残る間は予約スキルが6件、再Debug完了後は7件のツール参照を各1件持つことも確認します。ドラフトとチャネル未接続も再確認します。この時点の状態は「設定保存済み、動作未検証、未公開」であり、`テストを開始`、実通話、ツールのruntime実行、`公開`は別途確認します。

### 後続テストの合格条件

- 予約問い合わせでは、先行応答が本回答前に1回だけ発話され、同じ処理中に繰り返されない。
- サービスと空き枠を取得でき、予約作成前にサービス、日付、時刻への明示同意を得る。同じ予約意図で重複作成しない。
- 変更と取消の前に予約を取得し、同意対象のversionからstrong `If-Match`を作成する。
- `412`、非2xx、応答不明では変更系ツールを自動再実行せず、予約を再取得して実状態を確認する。
- `bulky-waste`では変更系ツールを呼ばず、予約一覧要求では列挙せずに利用者が保管する予約IDを求める。
- テスト後もチャネル接続とPublishは別の公開判断として扱う。
