# 音声ボット作成

## 予約対応を音声Agentへ追加する

予約APIを使用する場合は、先に[予約APIツールテンプレート作成](./04_予約APIツールテンプレート作成.md)の8件を作成、確認します。公開音声Agentで使用する6件のうち、予約作成、詳細取得、完全更新、削除には`X-Reservation-Caller-Phone`を`From Variable`の変数ピッカーから選択する`global_system.Engagement.ANI`から渡します。Zoom公式のTool作成記事にある`global.system.engagement.ani`は同じ発信者番号変数の別表記ですが、設定時は手入力せず実画面のピッカーを使用します。部分更新は安全修正が完了するまで使用せず、変更は詳細取得、空き枠確認、完全更新の順で行います。発信者番号の設計、失敗時の確認順、公開条件は[予約API発信者番号所有者照合](./06_予約API発信者番号所有者照合.md)も確認します。

予約操作を含む構成は、ANI所有者照合を含むバックエンドをProductionへ切り替え、4件のツールテンプレートへ発信者番号変数を設定し、Debugと実通話の同一ANI・別ANI試験に合格するまで、管理者が制御するドラフトAgentだけに限定します。全条件を満たした後は公開音声チャネルで予約の作成、確認、変更、取消を許可できます。ANIは通話の継続性を区切るデモ用の境界であり、行政手続きにおける強い本人確認ではありません。

### スキルを設定する

1. 対象の音声Agentを開きます。公開前の設定中は`ドラフト`にし、既存の公開版へ未検証の変更を反映しません。
2. `スキル`で`問い合わせ確認中の先行応答`が存在し、`Active`であることを確認します。存在しない場合は追加を推測せず、この手順を停止してSkill Library版と対象Agentの互換性を確認します。
3. 2026年9月1日に確認した対象音声Agentでは、Generalスキル`未来市の予約案内・予約管理`の`ライブラリから追加` → `Use`が`skill.channel=3 incompatible with agent.channel=2`で失敗します。同じ失敗操作を繰り返さず、スキル一覧の`スキルを作成`を開きます。別のAgentで追加を試す場合も、同じエラーが表示されたら停止します。
4. Skill Library版と同じ名前、トリガー、指示を設定し、`スキルライブラリに追加`はオフにします。
5. `挿入` → `ツール`から次の6件を各1件追加します。各ツールの`ツールの確認と追加`では、保存済みの静的Authorizationを外部へ表示、コピー、変更せず、同一アカウントの承認済み設定であることを確認して`保存して追加`を実行します。

   - `mirai_reservation_list_services`
   - `mirai_reservation_get_availability`
   - `mirai_reservation_create`
   - `mirai_reservation_get`
   - `mirai_reservation_replace`
   - `mirai_reservation_delete`

   `mirai_reservation_list`は追加しません。予約一覧はAPIキー単位の管理用途であり、発信者単位に分離された利用者向け機能ではないためです。`mirai_reservation_update_partial`も安全修正が完了するまで追加しません。一部項目だけを変更する依頼でも、`mirai_reservation_get`で現状を取得し、`mirai_reservation_get_availability`で変更先を確認してから`mirai_reservation_replace`で全項目を送ります。

6. Tool Templateを更新した既存Agentでは、同名のローカルコピーは自動更新されません。作成、詳細取得、完全更新、削除の旧4件を外し、サービス一覧と空き枠取得だけの中間状態を一度保存します。開き直して最新テンプレートの4件を再追加し、各`ツールの確認と追加`で`X-Reservation-Caller-Phone`が必須、`From Variable`、`global_system.Engagement.ANI`であることを確認します。同じ保存操作で旧コピーと新コピーを並べると同名重複として拒否されるためです。
7. スキルを保存し、一覧で`未来市の予約案内・予約管理`が`Active`であることを確認します。保存ボタンのフォーカスだけを成功と扱わず、モーダルが閉じ、更新時刻が変わり、開き直して指示と6件の参照が残っていることを確認します。

Zoom公式手順はスキルのモダリティとしてGeneral、Voice、Chatを案内していますが、実測エラーに含まれる内部チャネル番号の対応関係は公開していません。そのため、エラー文字列をモダリティ番号の仕様として一般化せず、対象Agentごとに追加結果を確認します。

Agent内で作成したスキルはSkill Library版とは別管理です。ツールテンプレートまたはSkill Library版を変更しても自動同期されたと扱わず、Agentローカル版の指示と6件のツール参照を開き直して手動で照合します。

Agent guidanceの禁止事項は権限制御ではありません。APIは予約ID、APIキー、`X-Reservation-Caller-Phone`の同一性をserver-sideで照合します。欠落と形式不正は400、別ANIと所有者情報のない旧予約は予約内容を返さない404です。Agentの外向き案内はどちらも同じ非開示文へ寄せます。公開前に、Zoom側の4件の書き込み・所有者付き読み取りツールがすべて`global_system.Engagement.ANI`を渡すことを保存後に読み戻し、同一ANIだけが後続操作できることを実通話で確認します。

`mirai_reservation_update_partial`は、GET非200の安全分岐とANIヘッダー伝播をZoom側テンプレートへ反映し、正常系200と制御された404を再Debugするまで完了扱いにしません。この既知未確認が残る間は、Agentローカルスキルへ同ツールを追加せず、残り6件だけを参照させます。

### Agent guidanceを設定する

`エージェントのガイダンス`の末尾へ次を追加します。

既存の全般指示に「予約確定を完了したと表現しない」という一律禁止がある場合は、次の範囲指定へ置き換えます。

```text
不要な個人情報や機微情報を求めず、本人確認、行政判断、行政申請、料金算定、処理券発行、正式受付番号発行を完了したと表現しないでください。予約APIが成功を返した場合に限り、このデモ用予約記録の作成、変更、取消が完了したと案内できます。
```

```text
【予約対応】

- 予約可能なサービス、空き枠、予約IDによる内容確認、予約の作成、変更、取消には「未来市の予約案内・予約管理」を使用してください。
- 予約に関するナレッジ確認またはツール実行が必要な場合は、本回答の前に「問い合わせ確認中の先行応答」を一度だけ使用し、その発話を完了してから予約スキルを使用してください。挨拶、すぐ回答できる確認質問、同じ処理の継続中には繰り返さないでください。
- 公開音声チャネルでは、発信者番号がシステム変数からツールへ渡され、API側のANI所有者照合が有効な場合だけ、予約の作成、詳細取得、変更、取消を実行してください。発信者番号を利用者へ質問したり、復唱したり、LLM入力から補ったりしないでください。
- 発信者番号が非通知、空、E.164形式以外、作成時と不一致、または所有者情報のない旧予約の場合は、予約の存在や内容を明かさず「この通話では予約を確認できません」と案内してください。別の番号を発話してもらって再試行しないでください。
- 予約一覧は使用しないでください。既存予約は利用者が提示した予約IDだけで取得し、他の予約を検索、列挙、推測しないでください。
- serviceKeyがbulky-wasteの場合も、日付と空き状況だけのデモ用予約記録は作成、確認、変更、取消できます。このデモでは品目、大きさ、数量、住所、排出場所を質問、収集、予約APIへ記録せず、料金算定、処理券発行、正式受付番号発行、行政上の収集申込み完了とは案内しないでください。正式申込み手順を質問された場合は、FAQに基づいて利用者自身が確認する事項として案内するだけにしてください。
- 音声チャネルでは自チャネルを「このチャット」と呼ばず「この通話」と案内してください。利用者が転送を断って通話終了を明示した場合は、同じ制約説明や転送提案を繰り返さず終了してください。
- 予約作成前にサービス、日付、時刻を提示し、利用者の明示的な確定意思を得てください。同じ予約意図には同じIdempotency-KeyとexternalReferenceIdを使用し、新しい識別子で重複作成しないでください。
- 変更または取消の前に予約IDで最新内容とversionを取得し、変更前後または取消対象を提示して明示的な同意を得てください。同意対象のversionからstrong If-Matchを作成してください。
- 部分更新ツールは使用しないでください。一部項目だけを変える場合も、詳細取得、変更先の空き枠確認、完全更新の順で実行してください。
- 412、非2xx、応答不明など変更結果が曖昧な場合は自動再実行しないでください。最初に予約を再取得し、現在内容とversionから適用済みかを確認して説明してください。追加操作が必要なら再度明示的な同意を得てください。エラー時は成功と案内しないでください。
```

文面を貼り付けた後、`挿入` → `スキル`から`未来市の予約案内・予約管理`と`問い合わせ確認中の先行応答`を各1件追加し、構造化されたスキル参照として保存します。文面中のスキル名だけを参照設定済みの証拠にしません。

保存後に画面を再読み込みし、予約スキルと先行応答スキルがどちらも`Active`、`mirai_reservation_list`と`mirai_reservation_update_partial`が0件、Agent guidanceの予約対応節と2件のスキル参照、6件のツール参照が保持されていることを確認します。公開前は[予約API発信者番号所有者照合](./06_予約API発信者番号所有者照合.md)の公開判定を実施し、未確認項目があればドラフトへ戻します。

### 後続テストの合格条件

- 予約問い合わせでは、先行応答が本回答前に1回だけ発話され、同じ処理中に繰り返されない。
- サービスと空き枠を取得でき、予約作成前にサービス、日付、時刻への明示同意を得る。同じ予約意図で重複作成しない。
- 作成、取得、完全更新、削除がすべて`global_system.Engagement.ANI`由来の同じ発信者番号を渡し、Agentが番号を質問、復唱、応答へ出力しない。
- 変更と取消の前に予約を取得し、同意対象のversionからstrong `If-Match`を作成する。
- `412`、非2xx、応答不明では変更系ツールを自動再実行せず、予約を再取得して実状態を確認する。
- 同じ予約IDでも別ANI、非通知、形式不正、所有者情報のない旧予約では内容、存在、件数を漏らさず拒否する。
- `bulky-waste`では日付だけのデモ予約を作成、変更、取消できる一方、品目、大きさ、数量、住所、排出場所を質問、収集、記録せず、料金、処理券、正式受付番号、行政申請完了を確定しない。
- 音声Agentは「この通話」と案内し、転送を断って終了を明示した利用者へ同じ制約説明や転送提案を繰り返さない。
- 予約一覧要求では列挙せず、利用者が保管する予約IDを求める。
- Previewでは`Start test with variables`で管理者がE.164のテスト値を明示設定する。Previewだけの成功を実通話のANI自動連携の証拠にしない。
