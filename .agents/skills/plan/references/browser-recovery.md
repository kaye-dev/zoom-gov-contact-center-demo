# Browser recovery

> Historical reference only. This document describes stored detailed-parity tooling and records. Plan, implement, review, and shipping use the smoke contract in `workflow-verification-contract.md`; do not execute or require the procedures below for feature work.

After an explicitly requested DPR recovery, the common Browser executor may call `recoverDprTerminalBatch({ repositoryRootPath, runId, batchId, adapter, tabs })` once for a terminal `PARITY_DPR_OVERRIDE_UNAVAILABLE` batch with no result fragment. Run current contract/source preflight and runtime ownership checks first. The function uses fresh `BrowserParityRunner` canaries on both manifest origins through the common two-tab adapter, requires 390×844 / DPR 1, screenshot digests, declared network capability, and validated cleanup. It checks manifest/checkpoint drift before writing. Failed canary or cleanup leaves the checkpoint untouched. Success retains previous attempts and failure provenance in that batch's `dprRecovery`, preserves all passed batches/fragments/artifacts, and makes only the named batch pending. It does not reserve work: call `executeBrowserBatch` next, without `resume-run` or `next-batch`. A repeated DPR failure, another terminal error, an existing result, or concurrent running work cannot use this recovery. Canary success authorizes only resumption, never coverage completion.

### Interrupted navigation recovery

After an explicitly requested continuation, `recoverNavigationTerminalBatch` may recover one terminal `PARITY_UNEXPECTED_ERROR` batch only when its recorded failure identifies the `navigate` operation, contains no row result, and has successful cleanup. Pass the recorded failure basename as `failureFile`. It verifies both origins with fresh common-runner DPR canaries, requires successful cleanup and unchanged manifest/checkpoint, records the failure digest, and permits only the second attempt. Passed fragments and assertion failures remain unchanged. This is not a permission bypass or a general terminal retry.

`recoverCaptureTerminalBatch` applies the same one-retry and artifact-retirement rules to a recorded unexpected `runProbe` exception only when the immutable profile identifies that probe as a screenshot and the failed row belongs to the batch. Required-probe failures, comparison failures, and arbitrary non-image probes cannot use this recovery.

When the user has closed crashed tabs, `recoverClosedTabsTerminalBatch({ repositoryRootPath, runId, batchId, adapter, tabs, failureFile, browser })` handles a recorded navigation exception with `PARITY_CLEANUP_FAILED` once. It requires the failed cleanup tab IDs to belong to the preceding verified surfaces, live Browser inventory to prove those tabs are absent, both replacement surface tabs to be present, and the original Browser session to be retained. It repeats the inventory check after fresh two-origin canaries and successful cleanup. A live failed tab, reappearing tab, missing replacement, assertion failure, changed session, failed canary/cleanup, drift, or second attempt leaves the terminal checkpoint unchanged. The original failure remains a failure; the separate `tabClosureRecovery` records retired tabs and fresh canaries without claiming a viewport readback from a closed tab. Earlier passing evidence is preserved.

If closed comparison tabs must be replaced, subsequent fragments may use the complete tab pair observed by a successful recovery at or before that batch. The recorded canaries must match the original Browser session, both manifest origins, 390×844 / DPR 1, screenshot digests, and successful cleanup. Mixing original and replacement tabs is invalid. Earlier fragments remain bound to their original tabs; final cleanup is checked against the final fragment's verified pair.

Source-changing invalidation moves affected batches' recovery records into `recoveryHistory` while resetting their result attempts. Those historical canaries cannot authorize replacement tabs in the new source epoch. Invalidation without changed source digests retains the active recovery guard. Recovery artifact archive names distinguish source epochs so earlier diagnostic artifacts are preserved.
