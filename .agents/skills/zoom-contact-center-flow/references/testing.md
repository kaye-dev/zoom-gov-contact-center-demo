# 検証用シナリオ

補助処理を変更した場合、スキルの配置先を指定して実行する。

```sh
python3 -m unittest discover -s "$SKILL/scripts/tests" -v
python3 "$SKILL/scripts/tests/evaluate_examples.py" --out /absolute/path/new-evaluation-directory
```

標準ライブラリのテストで、実際のJSON・グラフ・SVGの検査結果・同等性判定を確認する。skill-creatorのquick_validateも実行する。quick_validate用のPyYAMLがホストにない場合は、その検証だけ一時的な依存環境で実行できる。補助CLIの実行依存には追加しない。

## 回帰ケース

- 匿名化した15ノード・44接続のグラフ → 全分離で208ノード・207接続。構造上の開始から終端までの124経路を維持する。
- 標準reuseでは15ノードを保持し、座標以外を変更しない。指定分離／切断終端のみの分離も、それぞれの対象範囲を守る。
- 単一・複数ノードの循環を保持し、無限展開しない。到達性、欠けた出口、参照切れ、重複条件、名前の衝突、内部IDの衝突を検出する。
- 外部IDを保持し、同等性検証でその改変を検出する。改変された証跡が外部IDの比較を無効化できないことも確認する。
- 未分類ID、内部参照、式、変数スコープのある自動複製を保留する。未知メタデータは配置・分離後も保持する。
- 展開予定数を先に計算し、ローカル予算／確認済み上限を超える場合は生成しない。
- 全チャネルの分類・プロファイル拡張インターフェースと、不明な識別値を音声へ代用しないことを確認する。他チャネルのテスト識別値は合成値であり、Zoom実形式の検証証拠ではない。
- 元ファイル不変、既存出力上書き拒否、読み戻し、仮値を納品準備完了にしないことを確認する。

## 代表的な依頼を処理する

`evaluate_examples.py` は、下記の依頼からCodexが作成した具体仕様を使い、CLIを実行する。

1. 「音声で『受付を終了します。』と案内し、再生失敗時も含めて切断するフローを作成してください。」
2. 「案内だけを『またのご利用をお待ちしています。』に変更してください。」
3. 「処理と接続を保ち、重ならない程度に余白を詰めてください。」
4. 「全ての合流を分離し、終了経路を保ってください。」

新規作成と編集は正常・失敗の経路、案内文と終了動作のassertを照合する。生成されたflow.json、flow.svg、verification.json、summary.mdを実際に読む。SVGは適切な表示倍率で全体と分岐近傍を確認する。

これは「自然言語から人手（Codex）で作成した仕様の実行評価」であり、別モデルによる独立評価や自動スキル起動の実測ではない。形式検査だけで意図理解能力を保証しない。未取得チャネルのJSON生成やZoomへの取り込みは未実施として扱う。

今後の実依頼では、ユーザー要件と実際の分岐／文言／接続先の一致も確認し、誤った判断が見つかった箇所だけ改善する。合成fixtureのパスや固定ノード名を実案件の前提にしない。
